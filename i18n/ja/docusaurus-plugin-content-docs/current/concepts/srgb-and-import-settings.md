# sRGB とインポート設定

**このページを読むと** 「マスクを接続したのに効果がおかしい」の最も多い原因である、インポート設定が分かります。

## sRGB をオフにする理由

sRGB（Color Texture）は Unity に **「このテクスチャは人の目で見る色である」** と伝えるチェックボックスです。オンのままだと Unity がガンマ補正をかけ、保存されたピクセルの値とシェーダーが読む値が変わってしまいます。

色であればそれで正しいです。しかし **マスクは数値** です。0.5 で焼いたグレーは、シェーダーでも 0.5 として読まれる必要があります。

| テクスチャの種類 | sRGB | 理由 |
|---|---|---|
| 白黒マスク（描く、画像、グラデーション、ブリッジ、マットキャップ光沢の出力） | **オフ** | 値がそのまま読まれる必要がある |
| マスクコンバイナーでまとめたパックテクスチャ | **オフ** | 4 チャンネルすべてが値 |


<!-- SCREENSHOT: sRGB (Color Texture) をオフにしたテクスチャの Import Settings -->

:::tip[Mask Maker が出力した白黒マスクは、すでに正しく設定されています]
**マスク出力** は白黒マスクを sRGB をオフにした状態でインポートします。確認が必要なのは、外部から持ってきたマスクだけです。
:::

## 確認と修正の手順

1. プロジェクトウィンドウでテクスチャを選びます。
2. Inspector で **sRGB (Color Texture)** のチェックを外します。
3. **Apply** を押します。押さないと反映されません。

## あわせて確認するインポート設定

| 設定 | マスクに推奨 | 理由 |
|---|---|---|
| sRGB (Color Texture) | オフ | 上記のとおり |
| Alpha Is Transparency | オフ | アルファをマスクのチャンネルとして使うとき、Unity が値を変えないようにするため |
| Compression | None または High Quality | ブロック圧縮はチャンネルを混ぜます。特に**パックされたテクスチャ**で、チャンネルが互いににじみます |
| Generate Mip Maps | 好みで | オンにすると遠くで境界が柔らかくなり、細いマスクはぼやけます |
| Wrap Mode | Clamp | マスクを UV の外側で繰り返す理由はありません |
| Max Size | 512～1024 | マスクは境界だけが重要です |

:::danger[パックテクスチャは圧縮に特に弱いです]
DXT や BC 系の圧縮は、チャンネルを独立して扱いません。R チャンネルの境界が G チャンネルににじんで見えるのはこのためです。[チャンネルパッキング](/concepts/channels-and-packing)したテクスチャがおかしいときは、まず圧縮を疑ってください。
:::

## UV を確認する

マスクは、本体のテクスチャと **同じ UV マップ** を基準に読まれます。マスクを接続したのに、まったく別の場所に効果が出る場合は、そのスロットが UV1 以外の UV チャンネルを使うように設定されている可能性があります。

Mask Maker は読み込んだメッシュの UV をそのまま使って作るため、ツールの中で作ったマスクは、本体と同じ UV を使います。
